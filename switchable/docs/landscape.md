## 2. In-Depth Tool Comparisons

### 2.1 Promptfoo (https://github.com/promptfoo/promptfoo)
- **Strengths:** Excellent CLI matrix runner, fast caching, broad provider support, deterministic assertions (`equals`, `contains`, `is-json`), and security red-teaming.
- **Where Open-Switch Differs:**
  1. *Statistical Honesty:* Promptfoo shows point scores (e.g. 88% vs 91%). If a sample size is small (e.g. 50 examples), an observed 3% delta is statistically indistinguishable from noise. Open-Switch calculates 10,000-resample bootstrap 95% confidence intervals and enforces a decision threshold based on the **lower CI bound**.
  2. *Decision-First Output:* Instead of leaving the developer staring at an $M \times N$ matrix, Open-Switch delivers an executive recommendation: `Switch to Model X`, `Switch with Fine-Tuning`, or `No Safe Switch Found`.
  3. *Unit Economics & Break-even:* Open-Switch maps candidate token savings directly to enterprise monthly volumes and computes the exact break-even request threshold for fine-tuning.

### 2.2 DeepEval & Ragas (https://github.com/confident-ai/deepeval, https://github.com/explodinggradients/ragas)
- **Strengths:** Strong RAG-specific metrics (hallucination detection, answer relevance, context recall).
- **Where Open-Switch Differs:**
  - DeepEval and Ragas are designed for software regression testing inside CI/CD test suites. They do not model cost-per-1k requests, Pareto frontiers, or migration viability for structured production workloads.

### 2.3 Production Gateways (LiteLLM, Portkey)
- **Strengths:** Unified API proxies for switching between frontier models at runtime.
- **Where Open-Switch Differs:**
  - Gateways help you switch models once you have decided to switch; they cannot tell you whether switching is safe, what the quality regression will be, or which rows are legally safe to train on.

## 3. Core Open-Switch Innovations

1. **The Provenance Guard as a First-Class Feature**:
   Training open models on synthetic outputs generated by closed models (like OpenAI or Anthropic) violates many commercial Terms of Service. Open-Switch tracks `reference_source` metadata on every row, defaults to `train_allowed=false` on all closed API and unknown sources, and blocks non-compliant training attempts with an unavoidable cryptographic/attestation gate.
2. **Swapped-Order Impartial Open Judge**:
   Standard LLM-as-a-judge prompts suffer from position bias (favoring Candidate A over B regardless of quality). Open-Switch runs each evaluation twice with reversed positions ($A/B$ and $B/A$). If verdicts contradict, the result is flagged as `inconsistent` rather than silently distorting win rates.
3. **Calibrated Against Human Truth**:
   The judge's agreement is quantified against blind human labels using Cohen's kappa. If $\kappa < 0.4$, Open-Switch flags the judge as unreliable and defaults to deterministic metrics.
4. **Closing the Loop with Fine-Tuning**:
   When zero-shot open models fall short of the parity threshold, Open-Switch evaluates whether fine-tuning a small open model (e.g. Gemma 2 2B via Tinker) closes the gap, benchmarked against a k-nearest neighbor few-shot baseline on the exact same held-out test split.
